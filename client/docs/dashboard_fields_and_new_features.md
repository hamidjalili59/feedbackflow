# راهنمای داشبورد جدید، شاخص‌ها و فیلدهای UI

این فایل توضیح می‌دهد هر بخش داشبورد از کجا می‌آید، چه کاری انجام می‌دهد و کاربر چطور باید از ویژگی‌های جدید استفاده کند. این نسخه برای UI واقعی است و نباید به عنوان demo/mock استفاده شود.

## منبع اصلی داشبورد

داشبورد از endpoint زیر خوانده می‌شود:

```text
GET /api/v1/dashboards/me?period=this_month&compare=previous_period
```

سرور براساس توکن کاربر نقش او را تشخیص می‌دهد و خروجی مناسب همان نقش را برمی‌گرداند. نقش‌های والد و دانش‌آموز نمای ساده‌تر و پاسخ‌محور دارند. نقش‌های معلم، مدیر، CEO، admin و super_admin نمای عملیاتی‌تر، ranking و تنظیمات مدیریتی دارند.

## فیلدهای اصلی `DashboardResponse`

| فیلد | کاربرد در UI |
|---|---|
| `role` | تعیین می‌کند داشبورد والد/دانش‌آموز یا مدیریتی نمایش داده شود. |
| `period` | بازه فعلی مثل ماه جاری، سه ماهه یا سال جاری. Dropdown بالای داشبورد این مقدار را تغییر می‌دهد. |
| `children` | برای والدین استفاده می‌شود و کارت فرزند، کلاس و پروفایل را می‌سازد. |
| `selected_child_id` | فرزند انتخاب‌شده برای فیلتر کردن داشبورد والد. |
| `survey_summary` | سه کارت «تمام شده»، «در حال انجام» و «در انتظار» را تغذیه می‌کند. |
| `latest_surveys` | کارت «نظرسنجی جدید» و «آخرین نظرسنجی‌ها» را تغذیه می‌کند. هر آیتم روی فرم مربوطه باز می‌شود. |
| `metrics` | تایل‌های داینامیک مثل آموزش، مشارکت، ارتباط با مدرسه، ورزش، انرژی و ... را می‌سازد. اگر شاخصی تعریف نشده باشد UI پیام خالی نشان می‌دهد و mock نمایش نمی‌دهد. |
| `charts` | نمودار خطی/area بالای داشبورد را می‌سازد. معمولاً برای مشارکت یا شاخص انتخاب‌شده استفاده می‌شود. |
| `activities` | بخش آخرین فعالیت‌ها و موارد عملیاتی را می‌سازد. |
| `rankings` | برای نقش‌های مدیریتی لیست بهترین/ضعیف‌ترین معلم، کلاس یا شعبه را می‌سازد. |
| `distributions` | توزیع‌های آماری مثل نقش‌ها یا وضعیت‌ها. |
| `metadata` | قابلیت‌های فعال سرور مثل `dynamic_metrics`, `targeted_assignments`, `audience_segments`. |

## شاخص‌های داینامیک

شاخص‌ها از endpointهای زیر مدیریت می‌شوند:

```text
GET /api/v1/metrics
POST /api/v1/metrics
GET /api/v1/metrics/{id}
PATCH /api/v1/metrics/{id}
DELETE /api/v1/metrics/{id}
GET /api/v1/metrics/{id}/mappings
PUT /api/v1/metrics/{id}/mappings
```

هر شاخص می‌تواند به یک یا چند منبع وصل شود:

- پاسخ یک فیلد خاص در فرم
- امتیاز کل submission
- درصد امتیاز submission
- تعداد submissionها
- منبع custom برای توسعه آینده

نمونه شاخص‌هایی که مدیر یا CEO می‌تواند تعریف کند:

| شاخص | نمونه mapping |
|---|---|
| آموزش | میانگین rating فیلدهای کیفیت آموزش |
| مشارکت | درصد یا تعداد submissionهای تکمیل‌شده |
| ارتباط با مدرسه | میانگین likert/emoji reaction مربوط به ارتباط والد با مدرسه |
| پشتیبانی علمی | میانگین فیلدهای پشتیبانی آموزشی |
| ورزش | میانگین فیلدهای فعالیت بدنی یا رضایت از برنامه ورزشی |
| انرژی و انگیزه | mapping به سوالات انگیزشی یا emoji scale |

منوی سه‌نقطه روی هر تایل شاخص کار می‌کند و جزئیات شاخص، کلید، مقدار، وضعیت و منبع محاسبه را نمایش می‌دهد.

## تقویم نظرسنجی‌ها

تقویم از endpoint زیر خوانده می‌شود:

```text
GET /api/v1/surveys/calendar?period=this_month
```

هر روز شامل این فیلدهاست:

| فیلد | کاربرد |
|---|---|
| `date` | تاریخ روز. |
| `label` | عدد روز برای کارت کوچک تقویم. |
| `weekday` | نام روز هفته. |
| `status` | وضعیت کلی روز: `empty`, `pending`, `completed`, `closed`. |
| `count` | تعداد نظرسنجی‌های آن روز. |
| `highlight` | آیا روز در strip بالایی برجسته شود. |
| `surveys` | لیست نظرسنجی‌های همان روز برای bottom sheet و navigation. |

دکمه «دیدن همه» bottom sheet کامل روزهای بازه را باز می‌کند. لمس هر روز، لیست نظرسنجی‌های همان روز را نشان می‌دهد و لمس هر نظرسنجی وارد فرم مربوطه می‌شود.

## فرم‌های قابل پاسخ و دسترسی

برای جلوگیری از این‌که کاربر کل فرم را پر کند و انتها خطای دسترسی بگیرد، قبل از نمایش step form این endpoint صدا زده می‌شود:

```text
GET /api/v1/forms/{id}/answer-access
```

اگر `allowed=false` باشد، همان ابتدا صفحه عدم دسترسی نشان داده می‌شود. اگر کاربر اصلاً اجازه دیدن فرم را نداشته باشد، سرور باید آن فرم را در لیست‌ها و `/surveys/me` برنگرداند.

## Assignment و Segmentها

فرم‌ها می‌توانند به audienceهای زیر assign شوند:

- کاربر خاص
- نقش خاص مثل والد، دانش‌آموز یا معلم
- گروه/کلاس/دپارتمان
- کل سازمان
- segment داینامیک مثل «شرکت‌کنندگان اردوی ۲۷ام»

endpointهای مرتبط:

```text
GET /api/v1/audience-segments
POST /api/v1/audience-segments
GET /api/v1/forms/{id}/assignments
PUT /api/v1/forms/{id}/assignments
```

## فیلد رضایت تصویری شبیه طرح

فیلدهای `emojiReaction` و `likertScale` در UI جدید به صورت پنج صورت رنگی نمایش داده می‌شوند:

1. بسیار ناراضی
2. ناراضی
3. معمولی
4. خوشحال
5. خیلی خوشحال / عالی

این فیلد برای سوال‌هایی مثل «از نحوه ارتباط با مدرسه چقدر رضایت دارید؟» استفاده می‌شود و با UI طرح ارسال‌شده هماهنگ شده است.

## Single Select و Multi Select

فیلدهای `singleChoice`, `quizQuestion` و `multipleChoice` با کارت‌های انتخابی جدید نمایش داده می‌شوند. ویژگی‌ها:

- انتخاب واضح با border و badge
- توضیح گزینه از `metadata.description`
- حالت دو ستونه در desktop و عرض‌های بزرگ
- شمارنده انتخاب برای چندانتخابی
- پشتیبانی از RTL و متن فارسی

## وضعیت آمادگی داشبورد والد و دانش‌آموز

داشبورد والد و دانش‌آموز از داده واقعی سرور استفاده می‌کند:

- والد: کارت فرزند، پروفایل، نظرسنجی‌های جدید، summary، تقویم، فعالیت‌ها و شاخص‌ها
- دانش‌آموز: پروفایل دانش‌آموز، نظرسنجی‌های خودش، summary، تقویم، فعالیت‌ها و شاخص‌های مرتبط

اگر شاخص، فرم یا تقویم خالی باشد UI پیام خالی نشان می‌دهد و داده mock استفاده نمی‌کند.
